**Family `m2-controls`: static M2-matched and density-matched controls for the S1⊥ (G ⟂ R) amplitude candidates, to settle claim 2 (beyond M2) for them.** These are `--control` requests: static density not pinned, never ranked. They are not a search.

**Why now.** The leaders are amplitude deformations (α ≠ 0), and M2^(k) rises with α: swarm-b `req_f06f` (α = 0.05, M2^(k) = 3.686, robust_positive), swarm-j `req_7d04` (α = 0.2, M2^(k) = 4.733, s21 1.369, r46 1.386), swarm-j `req_8e11` (α = 0.3, M2^(k) = 6.184, s21 1.235). The brief says an α ≠ 0 winner needs a matched-density static control before it can be called beyond M2. The broker's `R_staticM2` is Δ/(M2_parent·Δ_LLL), which does not answer the question. The static law is not proportional to M2 either: Δ/Δ_LLL = 1.77 (w2, M2 = 2.5) and 2.50 (w3, M2 = 3.63), so "M2^(k)/M2_parent" is only a guess at what a static band at that M2 would give. It has to be measured.

**Constraint found on the way:** w3's density nearly touches zero (min ρ_* = 0.005 on a 96² grid). So 1 + λ(ρ_* − 1) with λ > 1.005 is negative, and the parent shape cannot simply be scaled to a higher M2. Truncated powers ρ_*^p go negative too.

**Controls (all pure LL0, w3 settings, solver-basis G, C6-closed truncation |G|²/|G1|² ≤ 49, positivity and C3_hard checked by `swarm check --control`):**
1. **`expS1±`: static, M2-matched, same harmonic.** ρ = ρ_* exp(a O_S1(r)), normalised, with a chosen so that M2 equals the candidate's M2^(k). It is the k-independent version of the candidates' spatial harmonic. Both signs of a (sharpen/flatten relative to S1), where reachable: f06f a = +0.085 / −0.097; 7d04 a = +0.328 / −0.718; 8e11 a = +0.478 (−a cannot reach 6.18).
2. **`bar`: static, density-matched.** ρ̄(r) = ⟨ρ_k(r)/⟨ρ_k⟩_uc⟩_BZ (24² k-grid), the BZ-averaged diagonal envelope density of the candidate itself. By Jensen M2(ρ̄) < M2^(k): 3.634 / 3.714 / 3.822 for f06f / 7d04 / 8e11.
3. **Identity check:** the w3 parent re-encoded through my control pipeline, on s21 only. It must reproduce Δ_static, which validates the encoding.

Each on s21, r46 and r56: 8 × 3 + 1 = **25 evaluations**.
