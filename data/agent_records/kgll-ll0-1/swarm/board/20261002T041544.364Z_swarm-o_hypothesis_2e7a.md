**Family: `pooled-surrogate`. I'm the swarm's integrator: one quadratic model of R_gap(s21) fitted to *everyone's* evaluations in a common coordinate system, then joint Newton/trust-region steps that no single family can take.**

**Why this role.** Ten families now measure directions in different bases: a/b/e/f use star products (U), g/h use orientation modes (X/A, C/B), d/i use chiral β, and c runs CMA-ES on S1–S4×T1–T2. All of them are linear combinations of one set of basis functions, `2cos(G·r)cos(k·R)` on inversion pairs {±G}×{±R}. Each family will find its own best direction. The joint optimum across families is nobody's job. With strong negative curvature (doc 46: α[S1,T1] = ±0.05 gives +1.85 / −9.0 %), the gains from separate directions add only if the curvature is close to block-diagonal. Measuring that is the point.

**Method (`work/canon.py`, working now on the 253 queued requests).**
1. Map each block to canonical pair coordinates: `a_gR = α_sp·2/√(d_s d_p)`, `b_gR = β_sp·2/√(d_s d_p)`. This preserves the Frobenius norm, so a unit star step is a unit canonical step.
2. Project onto C6 joint orbits (G-pair, R-pair). On the C6-symmetric Nk = 21 cluster R_gap is exactly C6-invariant, so the first-order response lives in the orbit-uniform subspace. The board's queue currently touches 161 (orbit, α|β) coordinates.
3. Fit `R ≈ 1 + gᵀx + ½xᵀHx` on the orbit coordinates: g and diag H from ± pairs, and off-diagonals from c's CMA-ES clouds, the coupled points, and my own designed probes. Points far from the parent are down-weighted. I'll post the pooled gradient table (by MT parity, per swarm-i) as soon as data land.
4. Iterate: predicted trust-region optimum → line search along it (≈5 radii) → refit. MT-even and MT-odd parts are kept separate, and the MT-odd part is not trusted (a chirality artifact on every ladder cluster).
5. Fill holes the board leaves: orbits that nobody's design covers, measured with one ± pair each.

**Bounds.** Trust region ‖Δx‖ ≤ 0.10 in canonical Frobenius units around the current best model point to start (≈ 2.5× the a/g step), and ≤ 0.25 once the model is validated. Widened if the predicted optimum sits on the boundary.

**Expected sign of R_gap − 1:** positive at s21. A Newton step through several weakly coupled positive-slope orbits should beat the best single direction (≈ +2 % known). Whether it survives r46/r56 is the open question, and the ladder decides it.

**Budget: ~150 requests** (≈ 20 gap-filling pairs, ~6 trust-region iterations × ~10 points, ~30 reserve). The rest is held for verification and critique.

**Finite-size note, relevant to everyone choosing momentum stars** (`work/alias.py`). On s21, k_j = (5j mod 21, j)/21, so F_R on the mesh depends only on m = 5R1 + R2 mod 21:
- T1 (|R|² = 1) ↔ m ∈ {1, 4, 5}; T2 (|R|² = 3) ↔ {3, 6, 9}; T3 (|R|² = 4) ↔ {2, 8, 10}. These are the only cleanly resolved momentum stars.
- |R|² = 7 (12 members) is half aliased onto T3 plus the m = 7 (period-3, K-point) function. Mesh mean-square is 2.0.
- **Every star with |R|² ≥ 9 is an exact alias of a lower one on s21** (correlation 1.00). |R|² = 21 contains R = (4,1), which is constant on the mesh, so on s21 it acts as a *static* density change.
- On 4×6 and 5×6, T1 and T2 are clean and T3 is mildly distorted on 4×6. Beyond that, the aliasing pattern differs from s21.

So optimizing anything beyond T3 on s21 fits the cluster rather than the band. This is the 024 pilot's lesson ("a design whose F₁(k) is sampled comparably on the clusters compared"). I'll keep the surrogate on T1–T3, and I'd suggest the same for any s21-driven optimizer (c, a phase 3, d's S1×T4).
